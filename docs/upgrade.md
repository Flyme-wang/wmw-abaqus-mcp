# 源码候选版安装与验收

**6.0.0 仅同步 GitHub 源码，尚未创建正式 Release；离线测试通过不等于真实 CAE 卡顿问题已验收。** 源码副本用于后续受控验证。

## 当前会话

在用工作目录、插件缓存、用户环境变量和已有 CAE 进程均不由本次开发修改。不要把候选源码覆盖到正在使用的目录，也不要在当前会话中重跑加载器或停止桥接来切换版本。正在执行的脚本或求解不能因为 MCP 超时而自动终止。

## 为后续新会话准备

1. 将 GitHub 仓库克隆到独立目录，例如 `C:\AbaqusMcpCandidate\wmw-abaqus-mcp`，保留旧版本；也可解压交付的源码包。
2. 使用该目录的外部 Python 虚拟环境安装 `pip install -e .`。桥接端使用的 `abaqus_mcp_plugin.py`、`bridge_runtime.py` 和外部 `mcp_server.py` 必须来自同一版本。
3. 参考仓库根目录的安装说明准备菜单加载器。新加载器会把 `ABAQUS_MCP_HOME` 加入 GUI Python 搜索路径，以便找到运行时模块；应在用户决定迁移、且旧会话自然结束后的窗口安排应用。
4. 为用户之后自行打开的新 CAE 指定该目录；MCP 客户端同时指向该目录的 `mcp_server.py`。仓库提供 `examples/mcp_config.example.json` 作为路径示例。本次不写入本机客户端配置。
5. 新窗口选择未占用端口，并确认其版本为 **6.0.0**。旧会话和其计算继续按实际状态运行，不为新版本腾出端口而关闭旧进程。

## 新会话验收顺序

先检查版本、端口、工作目录及会话标识，再在独立空白测试环境验证以下行为；本次离线开发未执行这些真实 CAE 操作。

- 一个操作进行中时，另一个不同编号的操作收到 `BUSY`，不在稍后悄悄执行。
- 保留原请求编号，超时后通过 `get_request_status` 查询，不直接重发保存、划网格或提交命令。
- 尚未派发的过期操作不执行；已经派发的操作超时后保持 `timeout_pending`，实际完成后可取得回执并释放占位。
- `submit_job` 返回提交回执后，通过 `monitor_job_status` 观察真实作业状态。新计算仍须按具体模型的既有授权与资源规则提交。

GUI 原生 `sendCommand` 的耗时和 GIL 行为尚未通过本次离线测试验证。短回调不能保证几何、网格和显示等原生操作永远不占用 GUI。任何长时间不响应先保留日志并报告，不能添加自动关闭 CAE 或终止求解器的兜底路径。
